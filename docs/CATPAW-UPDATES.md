# 跟随 Catpaw 更新

保留现有结构：`vendor/catpaw` 保存上游原始源码；`src` 与 `scripts/adapt-*.mjs` 保存 Harness 适配。不要直接编辑 vendor 或 `.generated`。

## 本地更新

推荐一条命令完成本地同步、依赖更新、验证和打包：

```sh
npm run update:catpaw -- ../catpaw
```

默认目录为 `../catpaw`，功能源码读取它的 HEAD，插件版本直接采用本地 Catpaw `package.json` 中的版本号。Catpaw 为 `0.1.6` 就生成 `dsh-catpaw-0.1.6.tgz`；变为 `0.1.7` 就生成 `dsh-catpaw-0.1.7.tgz`。版本号修改尚未提交时也会同步；仅有源码提交、版本号未变时，插件仍使用同一版本号。

`npm run pack:plugin -- ../catpaw` 使用同一流程，先同步源码和版本，再验证、打包。插件的 `package.json`、锁文件、构建后的运行版本及安装包文件名保持一致。脚本不会独立递增插件补丁版本。

用 `--ref` 指定其他提交或标签时，源码与插件版本都取自该提交，便于复现旧版；默认值 `HEAD` 使用上述本地版本规则。加 `--check` 只生成报告，列出源码及插件版本变化，不修改快照或插件版本。版本无效时在修改前停止；其他检查失败时不生成新的安装包，保留已同步的变更供适配后重试。日志和结果在 `output/catpaw-update.log`、`output/catpaw-update-result.json`。

Catpaw 源码直接从本地读取，不拉取远程仓库。依赖需要升级时，npm 和运行时下载器可能需要联网。下面是分步操作：

```sh
# 只检查，报告保存在 output/catpaw-sync.md 和 .json
npm run check:upstream -- ../catpaw

# 同步当前源码及本地版本号
npm run sync:catpaw -- ../catpaw

# 或指定完整提交号/发布标签，同时使用该提交的版本号
npm run sync:catpaw -- ../catpaw --ref <提交号或标签>
npm run sync:catpaw:deps
npm run check
```

同步先导出完整 Git 提交并校验，再替换快照；导入失败保留旧快照，原 Catpaw 仓库不被修改。同步前校验现有快照，防止覆盖直接写入 vendor 的适配。重复同步相同提交不会产生源码变化。报告列出文件新增/删除/修改、接口新增/删除/签名变化、依赖差异和需要检查的适配位置。

`vendor/catpaw/SOURCE.json` 记录上游提交、该提交的版本号和文件 SHA-256。脚本分别检查源码变化和插件版本变化，不会漏掉只有版本号变化的更新。本次导入 `5c703811c179…`：本地工作区版本标记为 0.1.6，但该提交的 package.json 仍是 0.1.3，因此来源记录如实显示 0.1.3。

例如上述本地 Catpaw 对应插件 **0.1.6**，生成 `output/dsh-catpaw-0.1.6.tgz`；未来版本自动按同样规则跟随。界面和安装包使用插件版本；来源记录保留原始提交信息，供以后追踪和复现。

## 兼容性检查

`npm run check` 包含源码校验、适配审核记录、依赖与锁文件检查、构建、类型检查、同步脚本测试和真实 Electron 后台测试。任务取消或模型接入的替换位置不匹配、事件接口变化时，构建失败。

插件启动还会检查每个上游接口是否有后台实现或明确的浏览器替代。新增功能缺失时明确停止启动。接口覆盖不能代替行为测试；新增功能必须增加对应的回归用例。

`catpaw.config.json` 中的 `reviewSources` 是被插件替代或修改语义的上游边界。源码变化后，`catpaw-adapter-lock.json` 中的审核摘要会过期，构建指出具体文件。完成代码检查、适配与对应回归用例后，再将这些文件在 SOURCE.json 中的新摘要写入审核记录。**同步脚本不会自动确认审核。**

运行依赖按配置分类：通常直接跟随 Catpaw；React 由 Harness 提供，只检查兼容范围；桌面更新器明确排除；新增未分类依赖必须检查。`sync:catpaw:deps` 更新需要升级的运行依赖和锁文件，不替换宿主框架依赖。

## 插件内的新版功能

- 自动备份随插件启动，退出时停止并等待当前任务结束；默认每天一份、保留七份，使用插件独立数据目录。自定义目录选择窗口出现在运行 Harness 的电脑上，页面会先说明这一点。
- Harness 模型和 Catpaw 自配模型共用每日额度。Harness 当前只返回文本，按保守预估计入；已发起请求的失败或取消保留预估记录，不作为精确账单。缓存命中不产生新模型请求。
- 长文在发起请求的浏览器中确认，其他客户端不能代答。关闭页面、取消任务、超时不会继续生成。
- 应用更新通过 Harness 分发插件，不启动 Catpaw 桌面更新器。诊断同时包含插件版本与 Catpaw 来源版本/提交。

## 发布候选与回退

`npm run check` 通过后，用独立数据目录验证页面中的订阅、备份、恢复、额度与长文确认，以及旧版数据库的文章、已读、收藏状态，再运行：

```sh
npm run pack:plugin
node scripts/package-smoke.mjs
```

打包默认再次读取 `../catpaw`；使用其他目录或固定提交时，传入与同步时一致的目录和 `--ref` 参数。后一个命令安装到本项目隔离的 Harness 配置并在 19394 端口启动，供页面和停用/重启验收；完成后按 Ctrl-C 停止。包版本从 package.json 读取。正式版本仍需发布者完成安装验收后发布。

升级前导出阅读数据库备份。回退时先停止后台并保留升级后的数据副本，再恢复旧插件及兼容的升级前数据库备份。只回退代码不能保证已升级的数据库可被旧版读取。按 SOURCE.json 的固定提交重新同步时，应一起恢复匹配的适配记录与依赖。
